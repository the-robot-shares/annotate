# Changelog

All notable changes to `annotate.therobotlives.com`.

## 2026-10-17

- fix(embed): `/embed/callback` 500 on widget SSO popup sign-in (prod `sha-0ccdca9`) — `Annotate.Embed.OIDC.fetch_tokens/1` passed a keyword list to `OpenIDConnect.fetch_tokens/2` (openid_connect 1.0.1 merges it via `Map.merge/2`) → `BadMapError` mid code exchange; now an atom-keyed map. Unexpected exchange raises render the widget `annotate-auth-error`/`auth_failed` postMessage instead of an opaque 500 (token-shaped strings redacted in the warn log); IdP `?error=` redirects verify state and postMessage the allowlisted reason; visible fallback text on the callback page. Regression tests pin the map contract. PR #33.
- fix(embed): widget SSO sign-in died with an opaque 500 on `/embed/callback` — `Annotate.Embed.OIDC.fetch_tokens/1` passed a keyword list to `OpenIDConnect.fetch_tokens/2`, which merges its second argument as a map (`Map.merge/2`), raising BadMapError mid-exchange AFTER the session state/nonce checks had passed (session cookie posture was already correct: `_annotate_sso` SameSite=Lax, HttpOnly, max-age 900); the crash also printed the one-time authorization code into the logs. Now passes `%{code: …, redirect_uri: …}` (atom-keyed map, matching the scaffold SSO flow), any unexpected raise during the exchange is rescued into the widget error postMessage (`annotate-auth-error` / `auth_failed`) with the reason logged at warning level through a token-shaped-string redactor (never a 500, no secrets), IdP error redirects (`?error=access_denied…`) verify state then postMessage the allowlisted reason, the callback page carries visible fallback text for when postMessage/close cannot run, and `authorization_uri` params are atom-keyed per the OpenIDConnect spec. Tests: fetch_tokens contract pin, exchange-crash → 200 + redacted log, IdP error legs, no-code fallback, session-cookie SameSite/HttpOnly/Max-Age attributes (19 tests in `embed_auth_test.exs`, full suite 261 green).
- chart: pin `ANNOTATE_PUBLIC_API_BASE` in the backend env (`https://appDomain`) — the landing embed's api-base previously relied on the runtime.exs default; explicit so prod embed target survives default drift. PR #29 → stage → main (#30/#31).
- CI test fix: enable the Hologram runtime in :test (`HOLOGRAM_START=1` in config/test.exs, set before app boot) and add `mix holo.sync_assets` in front of the `test` alias — the :app priv copy runs before the :hologram compiler, so on a fresh build the client bundles were missing from the priv the test app reads and every Hologram page request (landing at `/`) 404'd through the Phoenix router (Hologram disabled) / 500'd (AssetNotFound). The sync skips when Mix's build priv is a symlink into the source tree (fresh builds), so `rm_rf` never deletes the source bundles through it. `mix format` clean. PR #27 → stage → main (#30/#31).
